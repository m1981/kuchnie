# F06 — Enriched Human-Readable Activity Log (`prompt_log.md`)

## Problem

The old `prompt_log.md` only stored the raw user message with a timestamp — no context about what the agent actually _did_. Opening it on Friday told you _what you asked_ but not _what changed_.

```markdown
## 2026-05-29 21:55:26

Please edit hinges to Blum
```

No file paths. No diffs. No session context. Useless as a work diary.

---

## Goal

Transform `prompt_log.md` into a human-readable **work diary** that lets you open it on Friday morning and immediately recall:

- What you asked the agent
- Which files the agent read, searched, or edited
- Exactly what text was added or removed (inline `+/-` diff)
- Which chat session the work belonged to

---

## Solution: Enriched Activity Log

### Log entry anatomy

````markdown
# 2026-05-30 ← date banner (once per calendar day)

## 14:07 · Session: f4a1b2c3 "Zawiasy Blum" ← time + 8-char session ID + title

> Popraw proszę opis zawiasów — użyj Blum Clip Top 110° ← your exact question

### 🛠 Agent actions

1. 🗺 **get_repo_map** — scanned repo index
2. 📖 **read_file** — `data/05_Montaz_i_Sprzet/zawiasy.md`
3. ✏️ **edit_file** — `data/05_Montaz_i_Sprzet/zawiasy.md`
    ```diff
    - Zawiasy standardowe bez marki
    - Kąt otwarcia: 90°
    + Zawiasy Blum Clip Top
    + Kąt otwarcia: 110°
    ```
````

### Tool rendering rules

| Tool | Icon | What is shown |
|---|---|---|
| `get_repo_map` | 🗺 | "scanned repo index" — no args dumped |
| `search_knowledge_base` | 🔍 | Search query string |
| `read_file` | 📖 | File path only — content body NOT dumped |
| `edit_file` | ✏️ | File path + inline `-`/`+` diff of search/replace text |
| `create_file` | 📄 | File path + all new lines with `+` prefix |
| Any failed tool | ⚠️ | Error message shown instead of diff |
| Unknown / future tool | ⚙️ | Tool name + args snippet + result snippet (120 chars) |

## Public API

### `log_turn()` — primary entry point

```python
def log_turn(
    user_message: str | None,
    tool_logs: list[dict] | None = None,
    session_id: str | None = None,
    session_title: str | None = None,
    log_path: Path | str | None = None,
) -> None:
````

Called by `ChatService.handle_turn()` after `process_chat_turn()` returns, so
`tool_logs` is fully populated with every tool call made during the turn.

### `log_prompt()` — backward-compat shim

```python
def log_prompt(prompt: str, log_path: Path | str | None = None) -> None:
```

Delegates to `log_turn(user_message=prompt)` with no tool data. Keeps any
code still using the old API working without modification.

### `MAX_DIFF_LINES: int = 30`

Module-level constant. Diffs longer than this are truncated with a notice.
Importable so tests can reference it without magic numbers.

---

## Design Decisions

| Decision                              | Rationale                                                                                                                        |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **`log_turn()` as primary API**       | Receives full `tool_logs` from agent — single call site in `ChatService`                                                         |
| **`log_prompt()` kept as shim**       | Zero breaking changes to any code still using the old API                                                                        |
| **Date banner deduplication**         | Scans end of existing log for last `# YYYY-MM-DD` line — O(1), avoids re-reading entire file                                     |
| **Session ID truncated to 8 chars**   | UUID is noise in a human diary; 8 chars is unique enough for reference                                                           |
| **`read_file` shows path only**       | Dumping file contents would make the log unreadable noise                                                                        |
| **`edit_file` shows inline diff**     | `- removed / + added` per line — immediately actionable, easy to spot mistakes                                                   |
| **`create_file` shows `+` lines**     | All new content visible at a glance without opening the file                                                                     |
| **`MAX_DIFF_LINES = 30`**             | Prevents megabyte diffs from bloating the log; truncation notice appended                                                        |
| **Log written after agent completes** | Tool logs are only available after `process_chat_turn()` returns; log placement at step 8 of `handle_turn` ensures complete data |
| **User message as blockquote `>`**    | Visually separates the question from tool output in any Markdown renderer                                                        |
| **Tool order preserved**              | Tools rendered in call order — mirrors the agent's reasoning chain                                                               |

## Call Flow

```
POST /api/chat
  └── ChatService.handle_turn()
        ├── 1. load_session()          — DB read
        ├── 2. generate turn UUIDs
        ├── 3. append user msg to UI state
        ├── 4. process_chat_turn()     — agent loop (may call N tools)
        ├── 5. append assistant msg to UI state
        ├── 6. build turn_ids list
        ├── 7. save_session()          — DB write
        └── 8. log_turn(              ← NEW: enriched diary entry
                  user_message,
                  tool_logs,          ← full list from agent
                  session_id,
                  session_title,      ← derived from _make_title()
              )
```
