You made a fantastic catch! If `system_instruction` is `null` in the API call, the LLM is flying blind without its core persona or agentic rules.

Moving system prompts from the frontend to backend Markdown files is a **massive architectural upgrade**, especially for agentic workflows. Here is the breakdown of why, followed by a commercial-grade implementation plan to keep it lightning-fast.

### Pros & Cons: Frontend vs. Backend Prompts

**Frontend Prompts (Your Current Setup)**

- **Pros:** Zero latency to switch modes in the UI; backend stays completely stateless.
- **Cons:**
    - **Maintenance Nightmare:** As your prompts grow to include complex agentic rules (like the ones we discussed for tool calling), your Svelte files will become massive and unreadable.
    - **Rebuilds Required:** To tweak a prompt, you have to edit TypeScript and rebuild the frontend.
    - **Security/Encapsulation:** The frontend shouldn't dictate the core "brain" of the backend agent.

**Backend Prompts (Markdown Files)**

- **Pros:**
    - **Developer Experience:** You get syntax highlighting and clean formatting in `.md` files.
    - **Hot Swapping:** You can tweak the prompt in your code editor, save the file, and the next chat message instantly uses the new prompt without restarting the app.
    - **Composability:** You can have a `base_rules.md` (how to use tools) and append `design_mode.md` to it dynamically.
- **Cons:**
    - Requires a new API endpoint so the frontend knows which modes are available.
    - Slight disk I/O overhead (reading the file on each request).

---

### How to Implement Backend Prompts (and keep it snappy)

To keep it snappy, we won't read the files from the disk on every single chat turn. We will read them once when the app starts, cache them in memory, and serve them instantly.

#### Step 1: Create the Prompts Directory

Create a folder in your project root called `prompts/` and add your markdown files.

**`prompts/base_agent_rules.md`** (This applies to ALL modes)

```markdown
You are an autonomous file-system agent for a kitchen cabinet builder.
CRITICAL RULES:

1. If asked to read or edit a file without a path, ALWAYS use `get_repo_map` first.
2. NEVER use `edit_file` without using `read_file` first.
3. Do not ask the user for permission to use tools. Just do it.
```

**`prompts/design.md`**

```markdown
You are an expert kitchen designer.
Focus on ergonomics, spacing, and aesthetics. Always check the repo map for design guidelines.
```

#### Step 2: Create a Prompt Manager (`src/prompt_manager.py`)

This class reads the files on startup and caches them in memory. It's incredibly fast.

```python
import os
from pathlib import Path
from pydantic import BaseModel

class PromptMode(BaseModel):
    id: str
    label: str
    eyebrow: str
    content: str

class PromptManager:
    def __init__(self, prompts_dir: str = "prompts"):
        self.prompts_dir = Path(prompts_dir)
        self._cache: dict[str, PromptMode] = {}
        self._base_rules = ""
        self.reload_prompts()

    def reload_prompts(self) -> None:
        """Reads all markdown files and caches them in memory."""
        self._cache.clear()

        # Load base rules
        base_path = self.prompts_dir / "base_agent_rules.md"
        self._base_rules = base_path.read_text(encoding="utf-8") if base_path.exists() else ""

        # Define your modes (You could also read this from a JSON config)
        modes = [
            {"id": "general", "label": "General", "eyebrow": "Workspace help", "file": "general.md"},
            {"id": "design", "label": "Design", "eyebrow": "Ergonomics and layout", "file": "design.md"},
            {"id": "assembly", "label": "Assembly", "eyebrow": "Build and fitting", "file": "assembly.md"},
        ]

        for mode in modes:
            filepath = self.prompts_dir / mode["file"]
            content = filepath.read_text(encoding="utf-8") if filepath.exists() else ""

            # Combine base rules with the specific mode persona
            full_prompt = f"{self._base_rules}\n\n{content}"

            self._cache[mode["id"]] = PromptMode(
                id=mode["id"],
                label=mode["label"],
                eyebrow=mode["eyebrow"],
                content=full_prompt
            )

    def get_all_modes(self) -> list[dict]:
        """Returns metadata for the frontend (excluding the heavy content)."""
        return [{"id": k, "label": v.label, "eyebrow": v.eyebrow} for k, v in self._cache.items()]

    def get_system_instruction(self, mode_id: str) -> str:
        """Returns the full prompt string for the LLM."""
        mode = self._cache.get(mode_id)
        return mode.content if mode else self._base_rules

# Singleton instance
prompt_manager = PromptManager()
```

#### Step 3: Update FastAPI (`main.py` & `schemas.py`)

Update your `ChatRequest` schema so the frontend only sends the `mode_id` (e.g., "design"), not the whole string.

```python
# src/schemas.py
class ChatRequest(BaseModel):
    session_id: str
    message: str
    mode_id: str = "general"  # Changed from system_prompt
    # ...
```

Expose an endpoint so the Svelte frontend can fetch the available modes:

```python
# src/main.py
from src.prompt_manager import prompt_manager

@app.get("/api/prompts/modes")
def get_prompt_modes():
    return prompt_manager.get_all_modes()

@app.post("/api/prompts/reload")
def reload_prompts():
    """Call this if you edit a markdown file and want to refresh without restarting."""
    prompt_manager.reload_prompts()
    return {"success": True}
```

Finally, in your `/api/chat` endpoint, resolve the `mode_id` to the actual text before passing it to the service:

```python
# Inside @app.post("/api/chat")
system_instruction = prompt_manager.get_system_instruction(request.mode_id)

final_text, tool_logs = await loop.run_in_executor(
    None,
    partial(
        service.handle_turn,
        session_id=request.session_id,
        user_message=request.message,
        system_prompt=system_instruction, # Pass the resolved markdown text here!
        # ...
    )
)
```

### Summary

By doing this, you achieve **Separation of Concerns**. Your frontend only cares about UI (Labels and Eyebrows). Your backend handles the heavy lifting of Agentic Prompting. Because the files are cached in memory via `PromptManager`, there is **zero disk I/O penalty** during the chat loop, keeping the app incredibly snappy.
